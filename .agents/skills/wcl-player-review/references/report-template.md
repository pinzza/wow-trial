# 报告骨架与写法规范

## 命名与存放

```
data/reports/{专精}_{角色名}_{主题}_{副本中文名}+{层数}.md
data/reports/{专精}_{角色名}_{主题}_{副本中文名}+{层数}.pdf
```

实例：`武器战_开冲开冲_毒牙祭坛+9_输出水平诊断.md`、`奶骑复盘_口水披萨猫_铸光者_+12纳洛拉克之巢.md`

路径含中文/生僻字时**必须加引号**。

---

## 通用写法规范

| 项 | 规范 |
|---|---|
| 表格数字 | 右对齐 `|---|---:|` |
| 单位 | 统一：万 / M / min / 次/分钟；同一张表内不混用 |
| 时间 | 统一 `mm:ss`（战斗内相对时间） |
| 技能名 | 中文名 + 首次出现时附 spell_id |
| 评分 | **不给数字分**；用"定位句 + 严重度排序 + P0/P1/P2" |
| 措辞 | 中性；禁止讽刺、反讽、情绪化形容词 |
| 每条改进 | 必须挂**数字依据** |
| 结论 | 必须区分客观因素 vs 个人可改，给百分比拆解 + "合理上限"估数 |

## DPS 报告骨架（8 节）

```markdown
# {专精}输出水平诊断 — {角色名}（{副本} +{层数}）

| 项 | 内容 |
|---|---|
| 分析对象 | {角色名} · {专精} · {英雄天赋} · ilvl {X} |
| 对标榜样 | {角色名} · +{层数} · ilvl {Y} |
| 同层对照 | {角色名} · +{层数} · ilvl {Z}（若有） |
| 装等基准 | {基准技能}（spell_id {N}）每发伤害 |
| 数据来源 | WCL V1 API → SQLite（{code}.db 等） |
| 生成日期 | {YYYY-MM-DD} |

## 一、结论摘要
（表格 5–7 行：装等能解释多少 / 单发质量是否达标 / 真实差距在哪 /
 最明确的循环问题 / 环境因素 / 最容易改的一项）
**一句话总结**：……

## 二、分析对象与方法
- 三对象对比表（层数 / 装等 / 武器 / 原始 DPS / 活跃时间 / 死亡 / 消耗品 / 完成时间）
- **为什么用 {基准技能} 做标尺**（引用块，写清选型理由）
- 天赋/英雄天赋一致性的论证

## 三、拉平装等
3.1 基准标尺表（每发伤害 / 相对值 / 含义）
3.2 **多技能交叉验证表**（8–10 个技能的非暴击每发比值 → 验证标尺成立）
3.3 拉平后手法倍率表（逐技能，标注归因：装等/目标数/爆发窗口/个人）
3.4 总量与 DPS 对比表
3.5 **差距乘性分解** + 回验算式

## 四、施法顺序：平稳期 vs 爆发期
4.1 循环结构与技能优先级表
4.2 爆发窗口拆解表（窗口 GCD 数 / 窗口内各技能密度）
4.3 **实拍施法序列**（代码块，用 `技能A → 技能B` 箭头链，引用具体时间戳）
4.4 断档分析表（含与队友断档时间点对比）

## 五、{同层对照 / 与对标的综合对比}
（维度对比表 + 死亡时刻表）

## 六、装备与消耗品
6.1 装备硬差距表（ilvl / 武器 / 属性 rating / 套装）
6.2 消耗品对比表（合剂 / 食物 / 符文 / 药水，用 ✓ ✗）
6.3 天赋差异

## 七、综合水平结论
- 7 维度评级表（偏弱 / 合格 / 良好 / 优秀）
- 综合定位句
- 3–4 条推论

## 八、改进清单
| 优先级 | 事项 | 依据 | 具体动作 |
|---|---|---|---|
| P0（立刻改） | ... | 数字 | ... |
| P1（本周内） | ... | 数字 | ... |
| P2（持续提升） | ... | 数字 | ... |

## 附录
- 数据来源与记录表（报告码 / fight / source / DB 路径）
- 关键口径定义（基准怎么算、k 因子、时间归一化）
- **方法局限**（样本量 / 端点缺失 / 无法验证的部分）
```

## 治疗报告骨架（6 节）

```markdown
# {专精}治疗复盘 — {角色名}（{英雄天赋} · {副本} +{层数}）

（元信息表同上）

> **可比性声明**：两份记录层数不同（+{a} vs +{b}），敌人血量与伤害差约一个数量级，
> 总治疗量 / HPS / 过量率**不可直接比**；本报告只比较与层数无关的手法型指标：
> CD 利用率、资源流转、救急技能使用、循环结构。

## 一、基础治疗手法与资源流转
1.1 治疗构成对比表（技能 | +a | +b | 备注；含总量与过量率）
1.2 占比解读（**先声明团队掉血/压力差异**，再谈单技能）
1.3 资源流转表（生成端 / 泄能端） + "产得多转得少"结论

## 二、救急能力
2.1 救急/自保技能对比表（次数 + 过量率）
2.2 逐条要点 + 与队伍死亡事件对照

## 三、可预见 AoE / 大额点名应对
3.1 大招 CD 利用率表（实际 / 理论 / 利用率）
3.2 敌我时间轴（等宽代码块，CD 释放点 vs 死亡/大额伤害点）

## 四、职业特色发挥（{英雄天赋}）
做对 / 做漏 两栏并列

## 五、综合水平结论
一句话定位 + 按严重程度排序的问题 + "做得还行"

## 六、改进优先级清单
P0 / P1 / P2 表（改进项 + 具体动作，如"复仇之怒目标 26 分钟 10 次以上"）
```

## 写作要点（会话中验证有效）

1. **结论摘要放最前面**，让用户 10 秒内拿到答案；细节放后面。
2. **"为什么用这个基准"必须写**——这是用户最会质疑的方法论环节。
3. **交叉验证表是可信度的来源**——多个技能的比值聚集在一起，读者才会信归一化。
4. **时间轴用等宽代码块画出来**，比一段文字描述有说服力得多。
5. **差距做乘性分解并回验**（`1.287 × 1.108 = 1.427 ✓`），读者能自己验算。
6. **改进清单每条挂数字**，并给"可立刻做的动作"（例：换合剂、补双符文、把 CS 窗口里的英勇打击从 0.11 提到 0.42）。
7. **"合理上限"估数**：给出"现有装备下合理 DPS 约 22–23 万（+10%）"这类可执行预期。
8. **做对的地方也要写**——保持"做对/做漏"对称，报告才是复盘而不是批斗。
9. **附录必须写方法局限**，尤其是：只有一次战斗样本、无法还原敌方时间轴、percentile 语义存疑。
