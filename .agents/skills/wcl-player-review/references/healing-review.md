# 治疗水平复盘：四个维度

> 治疗不能套用 DPS 的指标。DPS 看"产出多少"，治疗看"用在刀刃上没有"。
> 本文件来自一次完整的神圣圣骑士（奶骑·铸光者）复盘会话，含用户的 6 处专业纠正。

---

## 0. 治疗 vs 伤害：取数差异

| 维度 | 伤害 | 治疗 |
|---|---|---|
| 端点 | `tables/damage-done` | `tables/healing` |
| 必备参数 | `sourceid` + `by=ability` | **`start` + `end` + `sourceid` + `by=ability`**（缺任一参数会静默返回 0 条） |
| 关键字段 | `amount` / `hits` / `crits` | `total`（有效治疗）/ `overheal`（过量） |
| 过量概念 | 无 | **有，且是核心指标** |
| 施法次数 | `ability.hits` | `tables/casts` 的 `total`（**唯一可信来源**） |
| 时间轴 | 基本不用 | **强依赖**：CD 释放点 + 敌方大额伤害/死亡点 |

**过量率**：

```
overheal% = overheal ÷ (total + overheal)
```

⚠️ **必须过滤 `total <= 0` 的负行**（存在如 `战火淬炼 Damage = -4,675,039` 的污染行，会把总量算错）。

**治疗三连取数**：`healing`（占比 + 过量）→ `casts`（次数）→ `events`（时间点）。

## 1. 维度一：基础治疗手法

**不是**单看"技能占比"，而是四件事合起来看：

1. 治疗构成占比（各技能 `total` ÷ 全队/自身总治疗）
2. 施法次数（只信 `tables/casts`）
3. 过量率（逐技能）
4. **资源流转：生成 → 泄能的转化率**

### 资源流转怎么读（以神圣圣骑士·圣能为例）

产豆端：审判 / 神圣震击 / 圣光闪现 / 神圣军备
泄能端：荣耀圣令（治疗）/ 正义盾击（伤害）

实测（+12 待分析 vs +21 对标）：

| | +12 | +21 |
|---|---:|---:|
| 审判（产） | 120 | 206 |
| 神圣震击（产） | 208 | 235 |
| 圣光闪现（产 + 治疗量） | 181 | 151 |
| 荣耀圣令（泄·治疗） | **108** | **232** |
| 正义盾击（泄·伤害） | 148 | 220 |
| 总治疗 | 147,043,850 | 297,791,248 |
| 过量率 | 38.5% | 29.8% |

**正确结论**："产豆端（闪现 + 震击 = 389 次）产得多，泄能端（圣令 108 次，不到对标 232 的一半）转得少；审判还少 86 次，进一步拖慢流转。"
**错误结论**："圣光闪现刷太多了。" ← 用户明确纠正过：闪现是产豆技能且治疗量大，打得多不是问题；**打得多还没转化成等量圣令才是问题**。

### 占比是相对量，禁止孤立评判

用户纠正 #1：报告把"神圣壁垒（被动盾）占比 19.4% ← 头号"判为"靠被动兜底"。

**实际**：该天赋下盾有主动/被动两种来源；占比高是因为**团队全程掉血少**，主动治疗空间小，持续吸收盾的相对占比自然被抬高。
**正确落点**：主动治疗（荣耀圣令 13.8%）占比偏低才是要点。

> **通用规则**：先看团队总掉血 / 层数 / 压力，再看单技能占比。低层压力小 → 被动/持续类占比必然偏高，不能当缺点。

## 2. 维度二：救急能力

看三个量：**次数 + 过量率 + 是否对应死亡事件**。

实测：

| 技能 | +12 | +21 | 判读 |
|---|---|---|---|
| 圣疗术 | 1 次 / **100% 过量**（total=0, overheal=763,000） | 4 次 / 30.4% 过量 | 100% 过量 = 白给，是问题 |
| 保护祝福 | 2 | 3 | 偏少 |
| 自由祝福 | 3 | 5 | 偏少 |
| 圣佑术（自保） | 10 | 21 | 见下方降级规则 |
| 清洁术 | 18 | 20 | 基本达标 |

队伍死亡 4 次（时间 / 死因）：1:15 腐烂地面、12:50 粉碎、15:39 狂怒飑风、16:25 寒冰暴雨。**救急技能的使用点要和这些死亡点对照**——没救到就是没救到。

**降级规则**（用户纠正 #3）：低层不危险导致"没意识开减伤"，属于**纪律性问题**，列为 P2 并写明"低层压力小是客观原因"，**不要**和"真浪费"混为一谈。
**但真浪费不留情面**：100% 过量的圣疗、CD 空转的大招，直接列高优先级。

## 3. 维度三：可预见 AOE / 大额伤害点名应对

核心指标：**大招 CD 利用率 = 实际释放次数 ÷ (战斗时长 ÷ CD)**。

实测：

| 技能 | CD | +12 实际 | +21 实际 | 理论（26:11 战斗） | 利用率 |
|---|---|---|---|---|---|
| 复仇之怒 | 2 min | **3** | 16 | ~13 | **23%** |
| 光环掌握 | — | 5 | 5 | — | 达标 |

**时间轴交叉**（本维度最有说服力的证据）：

```
AW 释放点:  4:06 ────────── 11.5 分钟空窗 ────────── 15:58 ─────── 25:46
队友死亡点:        1:15        12:50   15:39              16:25
                                            ↑
                          15:58 才开第二次 AW，比队友倒下晚 19 秒
```

**写法**：不要写"应该早点开"，要写"15:58 才开第二次复仇之怒，而队友已于 15:39 倒下，19 秒之差即『是否按时间轴开爆发』的差距"。

**时间戳归一化（必须）**：同一张 `event` 表里，death 事件的 timestamp 是**战斗内相对毫秒**，而 CD cast 事件是**报告内相对毫秒**。比较前必须减 `fight.start_time`：

```python
t_in_fight = cast_timestamp - fight_start_time
# 例: 7728000 - 7482072 = 245928 ms ≈ 4:06
```

**敌方技能时间轴**：V1 没有专门的敌方技能端点，只能从 `summary.deathEvents` 的 ability + event 表反查。实测敌方技能 cast 事件的 `source` 字段会落成玩家名，**字段映射不可靠，必须交叉验证**；拿不到就如实写"本次无法完整还原敌方时间轴"。

## 4. 维度四：职业特色发挥

**先确认英雄天赋**（这是最关键的一步），再检查"该天赋的核心按钮有没有卡 CD"，最后看**双轴**（治疗 + 输出）是否都转。

实测（铸光者神圣圣骑士）：

| 项 | +12 | +21 | 判读 |
|---|---|---|---|
| 神圣军备（核心，432459 壁垒形 25 + 432472 武器形 24） | 49 | 53 | 基本卡 CD → **做对** |
| 神圣震击（卡 CD 输出/产豆） | 208 | 235 | 做对 |
| 清洁术 | 18 | 20 | 做对 |
| 审判 | 120 | 206 | 做漏 |
| 正义盾击（伤害泄能） | 148 | 220 | 做漏 |
| DPS | 31,793 | 81,554 | 双轴只转了一半（约四成） |

报告里用"**做对 / 做漏**"两栏并列呈现，保持对称，不要只写缺点。

## 5. 英雄天赋陷阱（历史事故，必读）

**事故经过**：模型第一次分析时写出"**圣洁鸣钟（Divine Toll）1 次（26 分钟）→ 灾难性空转，利用率 ~5%**"，并把它列为第一大问题。

**根因**：
- `tables/casts` 确实返回了 `圣洁鸣钟 guid=375576 casts=1`
- `ability` 表也有 `id=375576 hits=1`
- `player.hero_talent` 列是**空字符串**
- `ability` 表是**报告级聚合**（fight_id 恒为 1），单次异常施法可能来自别的 pull

**事实**：该角色是**铸光者**英雄天赋，**根本没有圣洁鸣钟这个技能**（该天赋用「神圣军备」替换了 Holy Prism / 圣洁鸣钟）。

**正确顺序（不可逆）**：

1. **先确认英雄天赋**：`hero_talent` 列为空 → 用**标志性技能签名**反推（神圣军备 432459 / 圣洁武器 432472 与 圣洁鸣钟 375576 **互斥**），或读 `tables/summary` 的 `combatantInfo` 天赋树
2. **据此确定技能池**与"该卡 CD 的按钮"
3. **再评价手法**
4. 版本机制有疑问时先查权威来源（`warcraft.wiki.gg` 可用；wowhead 常 403）

**自查止损信号**：当 event 表的实例数（黎明之光 x190 ≈ 38 次施法）与 `casts` 端点（1 次）严重矛盾时，说明其中一方口径有问题 → 先查清再写结论，拿不准的技能**从批评列表里删掉**。

## 6. 治疗报告结构

固定 6 节：

1. **基础治疗手法与资源流转** — 治疗构成对比表 + 占比解读 + 资源流转表 + 转化率结论
2. **救急能力** — 圣疗/保护/自由/自保 对比表 + 逐条要点
3. **可预见 AoE / 大额点名应对** — CD 利用率表 + 敌我时间轴（等宽代码块）
4. **职业特色发挥** — 做对 / 做漏 两栏
5. **综合水平结论** — 一句话定位 + 按严重程度排序的问题 + "做得还行"
6. **改进优先级清单** — P0 / P1 / P2 表（改进项 + 具体动作，如"复仇之怒目标 26 分钟 10 次以上"）

**不给数字评分**。用"定位句 + 严重度排序 + P0/P1/P2 + 具体动作"落地。

**报告开头的可比性声明**（必备）：

> 两份记录层数不同（+12 vs +21），敌人血量与伤害差约一个数量级，总治疗量（1.47 亿 vs 2.98 亿）、HPS、过量率**不可直接比**；本报告只比较与层数无关的手法型指标：CD 利用率、资源流转、救急技能使用、循环结构。

## 7. 治疗分析复用清单

1. 先定层数与压力，再谈可比性：总治疗 / HPS / 过量率是层数的函数，**绝不跨层直接比**。
2. 先确认英雄天赋与版本，再确定技能池，最后评价——顺序不可逆。
3. 所有占比都是相对量：先看团队总掉血，再看单技能占比。
4. 产豆 / 泄能**成对看**：生成次数 → 泄能次数 → 转化率，而不是评价某个填充技能"打太多"。
5. CD 利用率 = 实际次数 ÷（战斗时长 ÷ CD），逐个大招算——这是最可跨层比较的手法指标。
6. 时间轴必须交叉：敌方大额伤害 / 点名 / 死亡点 vs 我方 CD 释放点，统一减 `fight.start_time` 归一化。
7. 救急看"刀刃率"：次数 + 过量率 + 是否对应死亡事件；100% 过量 = 白给，0 次 = 底牌没用。
8. 施法次数只信 `tables/casts`；event 表的 cast 行是实例流，仅用于取时间点。
9. 低层导致的保守降级为"纪律性建议"，真浪费（圣疗全过量 / CD 空转）直说。
10. 全程中性措辞，禁讽刺；结论 = 定位句 + 严重度排序 + P0/P1/P2 + 具体动作。
