# 方法论：装等归一化 · 指标清单 · 爆发窗口

## 1. 为什么要归一化

层数差会同时改变三件事：敌人血量、战斗时长、团队环境。所以**原始 DPS/HPS 不是一个可比量**。

实测反例（武器战）：
- 原始 DPS 202,362 vs 473,098 → 差 **2.338×**，看起来"完全不会玩"
- 拉平装等后 202,362 vs 288,854 → 差 **1.427×**
- 再拆开：其中大部分来自队伍拉怪规模与断档，**单发技能质量其实已经达标（0.94–1.07×）**

如果不做这一步，结论会完全反过来。

---

## 2. 基准技能选型规则

**必须同时满足**：

1. **纯单体** —— 伤害与目标数无关（AoE 技能会被拉怪规模污染，直接淘汰）
2. **每发伤害只随面板属性线性缩放** —— 不受爆发窗口、buff 覆盖率、触发影响
3. **样本量足够** —— 战斗内施放次数通常 ≥ 50，太少则均值不稳
4. **能拿到非暴击口径** —— 见下面"两个因子"

**不能做基准的**：
- 自动攻击（部分专精）—— 实测噬灭 DH 的 Melee 只有 4 万伤害，无意义
- 任何 AoE / 顺劈 / DoT 技能
- DoT 类（每跳受急速影响，会混入手法差异）

已验证的选型：

| 专精 | 基准 | spell_id | 选型理由（报告里的原话） |
|---|---|---|---|
| 噬灭 DH | 吞噬 Devour | 1217610 | 纯单目标泄怒技，每发与目标数量无关，只随面板线性缩放，是最干净的"装等标尺" |
| 元素萨满 | 闪电箭 Lightning Bolt | 188196 | 纯单体填充技，几乎不受爆发窗口、AoE 目标数影响，是衡量"裸装等差距"的最佳基准 |
| 武器战 | 自动攻击 Melee | 1 | 唯一纯武器伤害来源，不受技能优先级、爆发窗口、目标数量影响，永远单体 |

> 新专精请按同一规则自行选型，并在报告里**写明为什么选它**（用户会看这一条）。

## 3. 两个归一化公式（等价，按场景选用）

### 方案 1：换算成"基准单位"（适合表达"输出量/效率"）

```
baseline_per_cast = 基准技能总伤 ÷ 基准技能施法次数
归一总伤 = 玩家总伤害 ÷ baseline_per_cast        # 单位：个"基准技能"
active_time = damage_total ÷ dps                  # 秒
归一 DPS = 归一总伤 ÷ active_time                 # 单位/s
```

实测（噬灭 DH）：

| 对象 | 层 | 装等 | 吞噬每发 | 总伤 | 归一总伤 | 主动时间 | **归一DPS** |
|---|---|---|---|---|---|---|---|
| 丨万世创伤 | +12 | 310 | 79,878 | 233,113,262 | 2,918 | 18.9 min | **2.57** |
| 灬可乐喵丶（同层高手） | +12 | 315 | 90,062 | 264,663,219 | 2,939 | 13.6 min | **3.60** |
| Nynsa | +19 | 319 | 100,882 | 541,160,620 | 5,364 | 25.6 min | **3.49** |

**怎么读这组数**：归一总伤 2,918 vs 2,939（差 0.7%）→ 输出**量**不差；归一 DPS 2.57 vs 3.60（低 29%）→ 差在**效率**（同样多的伤害多花了 39% 的时间）。
两个高水平样本收敛到 3.49~3.60，虽层数差 7 层 → **归一化自检通过**。

### 方案 2：装等因子 + 手法倍率（适合逐技能归因）

```
装等因子 G = 对标基准每发 ÷ 我方基准每发
拉平后每发 = 对标每发 ÷ G
手法倍率   = 拉平后每发 ÷ 我方每发
```

实测（元素萨满，闪电箭 70,874 vs 78,609 → G = 1.109，即 308→315 装等只值 11%）：

| 技能 | 我方每发 | 对标每发 | 拉平后 | 手法倍率 | 归因 |
|---|---:|---:|---:|---:|---|
| 闪电箭 | 70,874 | 78,609 | 70,874 | 1.00× | 基准（装等） |
| 闪电链 | 166,670 | 207,850 | 187,387 | 1.12× | 目标数 |
| 元素冲击 | 268,225 | 383,963 | 346,154 | **1.29×** | 爆发窗口对齐 |
| 熔岩爆裂 | 207,181 | 365,282 | 329,318 | **1.59×** | 爆发窗口 + 烈焰震击覆盖 |
| 地震术 | 467,936 | 1,020,102 | 919,669 | 1.97× | 拉怪波次（次要） |

**读法**：倍率 ≈1.0 的技能说明"装等能解释完"；倍率明显 >1 的技能是**手法差**；倍率 <1 反而是你做对了。

## 4. 两个 k 因子：`k_nc` 与 `k_all`（**必须分开用**）

因为 V1 events 不返回 `crit` 字段，只能用 `hitType`（1=命中，2=暴击）自己拆：

```python
h = [r for r in rows if r.type == "damage" and r.hitType == 1]   # 非暴击
c = [r for r in rows if r.type == "damage" and r.hitType == 2]   # 暴击
mh = mean(h.amount); mc = mean(c.amount); ma = mean(h+c)
cr = len(c) / (len(h) + len(c))                                  # 暴击率
```

| 因子 | 定义 | 用于比较 |
|---|---|---|
| `k_nc` | 对标非暴击每发 ÷ 我方非暴击每发 | **"每发伤害"类指标**（逐技能倍率表） |
| `k_all` | 对标含暴击每发 ÷ 我方含暴击每发 | **总伤 / DPS** |

实测武器战：`k_nc = 18,048 / 11,776 = 1.533`（纯装等/攻强差距）；`k_all = 26,581 / 16,229 = 1.638`（叠加暴击率 40.5% vs 37.0%）。

⚠️ **把 `k_all` 拿去归除非暴击每发，会得到 0.88–1.01 的错误倍率。** 这是实际发生过的自我纠正。

## 5. 基准自检（强制步骤）

拿 8–10 个同伤害类型的技能，各自算 `对标非暴击每发 ÷ 我方非暴击每发`，检查是否**聚集在 k 附近**：

实测武器战：Melee 1.53 / MS 1.63 / OP 1.56 / Cleave 1.57 / Slam 1.61 / HS 1.44 / Reap 1.52 / 屠戮者 1.52 / 撕裂 1.65 —— 9/10 落在 1.44–1.65，均值 ≈1.55，白字 1.53 正中 → **标尺成立**。
唯一离群项：重伤 Deep Wounds 2.05 → **单独解释**，不要硬套。

**离散度很大 = 基准不成立**，此时应换技能，或放弃归一化并如实声明"本次无法剥离装等"。

**同层对照是最好的验证**：实测同层（+9 vs +9，ilvl 299 vs 302）比值 0.987 ≈ 1 → 基准可靠性得到第二重确认。

## 6. 指标清单

### 6.1 输出量 / 效率

| 指标 | 算法 | 意义 |
|---|---|---|
| 原始 DPS | `player.dps` | 不可跨层比 |
| 活跃时间 | `damage_total ÷ dps` | 分母；与战斗时长的比 = 活跃时间占比 |
| 输出 GCD 数 / 频率 | 自身 cast 事件（1s 内折叠）÷ 活跃分钟 | 手法密度 |
| 每输出 GCD 归一产出 | 归一总伤 ÷ 输出 GCD 数 | **最干净的效率指标** |
| APM | `player.parse_pct`(=total_casts) ÷ 活跃分钟 | 参考值 |

### 6.2 手法结构

| 指标 | 算法 | 判据 |
|---|---|---|
| 主技能占核心按键比 | 主技能激活数 ÷ 核心按键总数 | 与对标比 |
| **生成:泄怒比** | 资源生成技次数 ÷ 主泄怒技次数 | 资源循环类专精的核心（实测 DH 0.65/0.54/0.40 呈梯度） |
| 低价值技能:主技能 | 填充技次数 ÷ 主技能次数 | 实测 DH 收割:Devour = 15.2% vs 1.9%/1.7% → 多花 ~29 个 GCD |
| 技能优先级结构 | 各技能伤害占比 | 结构一致但次序错位是常见问题 |
| 斩杀 vs 主力占比 | 斩杀技占比 vs 主技能占比 | 实测"斩杀挤掉致死"（14.9% vs 9.0%） |

### 6.3 爆发窗口

| 指标 | 算法 |
|---|---|
| 爆发次数/分钟 | CD 技能次数 ÷ 战斗分钟 |
| **窗口灌满度** | 爆发窗口内 GCD 数（实测 CS 窗口 8.76 vs 9.73） |
| 窗口内技能密度 | 窗口内各关键技能次数（MS 3.81 vs 4.67、HS 0.11 vs 0.42） |
| 预铺覆盖率 | 爆发前 N 秒铺垫技能是否到位（实测升腾前 5s 风暴守护者 7/10 vs 9/10） |
| 强化资源去向 | 强化类 buff 消耗在哪个技能上（实测浪费在单体闪电箭 31 次 / 47% vs 16 次 / 35%） |
| 大招伤害占比 | 窗口内伤害 ÷ 总伤害（45.5% vs 46.7% → 利用率没问题） |
| CD 冷却中位数 | 相邻两次释放的间隔（36.1s vs 31.4s） |

### 6.4 环境 / 生存

- 活跃时间占比、`>6s` / `>15s` 断档次数与总时长（**必须与队友交叉验证**）
- 每发命中目标数代理（AoE 打得开不开）
- 死亡次数 + 死亡时刻 + 死因技能 id
- 打断次数（注意：某些专精**没有**打断技能，不得批评"0 次打断"）
- 消耗品：合剂 / 食物 / 符文 / 药水次数

## 7. 爆发 / 平稳期切分

切分锚点因专精而异，**必须写在报告里**说明用了什么锚点。

**通用做法**：把同一 `ability_id` 且在 **1.0s 内**的连续事件折叠为一次"激活"，用激活序列近似按键序列：

```python
if aid == last_aid and ts - last_ts < 1000:
    continue
```

**已验证的锚点**：
- 元素萨满：升腾（Ascendance 114050）后 15s 为爆发窗口；升腾前 5s 检查风暴守护者（191634）；窗口内统计熔岩爆裂(51505)、元素冲击(117014)、闪电链(188443)
- 噬灭 DH：坍缩之星（1221150）为锚。爆发 = 坍缩星 → 大灭(proc) → Devour ×3~4 连打；平稳 = 虚空射线（引导攒资源）→ 吞噬 Devour（泄怒）

**没有权威循环知识时**：只做"我方 vs 对标"的相对比较，不要写"正确循环应该是"。原话记录：*"I don't have authoritative knowledge of the 12.1 Devourer DH rotation. But I can still do a comparative analysis."*

## 8. per-cast 取数陷阱

**伤害表与施法表常用不同的 spell_id**，必须"按名字聚合总伤 ÷ 按名字聚合施法次数"：

- 地震术：伤害在 `id=77478`，施法在 `id=61882` → `59,895,793 ÷ 128 = 467,936`
- 熔岩爆裂有 `51505 / 447419 / 285452` 多个 id

**伤害表里 `casts = 0` 的行是被动/触发技能**（根除 / 虚落流星 / 灵魂爆发 / 大灭 / 剔除），不能当作"0 次施法"来分析。
