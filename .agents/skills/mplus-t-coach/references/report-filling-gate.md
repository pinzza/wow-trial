# 填充报告门禁协议（report-filling-gate）

> 适用：T 系列（mplus-t-coach）以及任何"把量化数据翻译成技能建议"的报告填充环节。
> 本文件为 `SKILL.md` Step 0 的强制前置。**门禁未通过 = 不得开始写报告正文。**

## 为什么需要门禁

历史事故：模型跳过知识卡片，凭记忆写技能建议，产出**该英雄天赋根本不存在的技能**（如给铸光者圣骑士写"圣洁鸣钟"），或写**机制方向相反的措辞**（如"预铺神龙之赐"）。这类错误会直接摧毁报告可信度，且用户一眼能看出。

## 门禁三关（全部通过才放行）

### 第 1 关：知识库完整性

- [ ] `data/taozhi/knowledge_base/孙青云/` 下 7 个文件齐全（`00_README.md` + 01~05 正文 + 转录勘误对照）
- [ ] `data/taozhi/lvlyue_benchmark_profile.json` 存在且非空
- [ ] 缺失时：**停下并报告**"知识库门禁未通过"，列出缺失文件；不要用记忆补位

### 第 2 关：技能机制确认

对**报告中将要出现的每一个技能名**，在卡片中找到出处：

- [ ] 该技能属于当前**英雄天赋 + 版本**的技能池（`03_孙青云-循环.md` / 天赋章节）
- [ ] 该技能的使用场景描述正确（可预铺 / 只能反应性释放 / 需提前开 / 需预判给）
- [ ] 对"预铺"类措辞逐条复核：**只有 HoT/护盾类可以预铺**，攒层数后爆发释放的治疗不属于预铺
- [ ] 减伤类技能区分"提前开"（大减伤）与"预判给"（外置减伤），不要一律写成"预铺"

### 第 3 关：数字依据与出口自检

- [ ] 每一条"需要改进"都挂了**具体数字**（次数 / 占比 / 利用率 / 时间点），没有形容词式结论
- [ ] 每个数字都能在 `data/taozhi/` 的基准或本次 WCL 数据中复现
- [ ] 术语与卡片一致（鹤僧 vs 龙僧、三板斧、神龙之赐层数……）
- [ ] 完全没有情绪化措辞（见根 `AGENTS.md`「报告产出与交付约定」）

## 出口验收

逐条朗读报告中的技能建议，对每一条回答：**"这条依据在卡片的哪一行？"**
答不出来的条目一律删除或降级为"待确认"，不得留在正式报告里。
